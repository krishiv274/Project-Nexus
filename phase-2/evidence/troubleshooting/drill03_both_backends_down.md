# Drill 3: Both backends down (application failure)

**Fault injected:** Backend A stopped on app01 **and** Backend B stopped on app02.

## Symptom
```text
$ curl -sS -o /dev/null -w '%{http_code}\n' https://app.cn.test/api/status
502
$ curl https://app.cn.test/api/status
<html><head><title>502 Bad Gateway</title></head> ... nginx/1.28.3 (Ubuntu)
```

## Commands run and observations (bottom-up)

| Layer | Command | Observation | Conclusion |
|---|---|---|---|
| 0 | `curl … /api/status` | `502 Bad Gateway`, generated by **nginx** | An HTTP response came back, so DNS, TCP and TLS all worked |
| 1 | `dig +short app.cn.test` | `10.211.55.6` | DNS is correct |
| 3–4 | TCP 443 and TLS | implied: curl received a valid HTTPS response with no certificate error | Transport and TLS are fine |
| 5 | HTTP status | `502` from the edge | The edge is up but has no working upstream |
| 6 | `nc -vz -w 3 10.211.55.7 3001; nc -vz -w 3 10.211.55.8 3002` on edge01 | *(next check by the method, not captured)* expected: both `Connection refused` | Neither backend is listening |
| 6 | `cn_error.log` on edge01 | *(not captured: this test ran before the Phase 2 log format was enabled)* expected: `connect() failed (111: Connection refused)` for both upstreams | Both backend processes are down |

## Layer identified
**Application (backend service failure).** Compare with Drill 1: there, `dig` fails and no connection is attempted;
here, `dig` works and the failure is behind the edge.

| | DNS failure (Drill 1) | Application failure (Drill 3) |
|---|---|---|
| `dig` | fails | `10.211.55.6` |
| TCP / TLS to the edge | never attempted | succeed |
| HTTP | none (`000`) | `502 Bad Gateway` from nginx |

## Fix
Start both backends (`python3 app.py` on app01 and app02). The next requests return `200` with A and B alternating.

## Lesson
A `502` is good news for the diagnosis: it proves everything up to and including the edge works, so the search
can start directly behind the edge.

**Evidence:** `images/p2_fig07_app_failure.png`. The single-backend version of the same error is in `vm_logs/edge01/cn_error.log` (Drill 2).
